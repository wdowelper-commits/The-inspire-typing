## 5. Supabase Integration Strategy

- Supabase client initialized in `src/lib/supabase.ts` using environment variables.
- **Never hardcode** Supabase URL or keys in source code.
- Use `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` for client-side.
- Auth: Supabase Auth with email/password + Google OAuth provider.
- All database operations via Supabase JS client (`supabase.from(...).select/insert/update`).
- RLS (Row Level Security) enabled on all tables — policies defined in Backend Schema.
- Real-time subscriptions: NOT used (no need for real-time in this app).

## 6. Authentication Approach

| Method | Detail |
|--------|--------|
| Email + Password | Supabase built-in auth |
| Google OAuth | Supabase Google provider |
| Session Management | Supabase session (JWT stored in localStorage by Supabase client) |
| Protected Routes | Custom `ProtectedRoute` wrapper component checking `authStore` |
| Admin Route Guard | Checks `user_role = 'admin'` from `profiles` table |
| Guest Mode | No auth required; `authStore.user` is null; no Supabase calls for data save |

## 7. Typing Engine (Core Logic)

Implemented in `useTypingEngine.ts`:

```typescript
// Key behaviors:
// - Input compared character by character to target text
// - currentIndex tracks position in target string
// - correct chars: green; wrong chars: red; untyped: gray
// - WPM = (correctChars / 5) / elapsedMinutes
// - CPM = correctChars / elapsedMinutes
// - Accuracy = (correctChars / totalTyped) * 100
// - Mistakes = count of wrong characters typed
// - In TEST mode: backspace tracked as mistake; word cannot be "un-wronged"
// - In LESSON mode: backspace allowed for correction
```

**Urdu Support:**
- Input field set to `dir="rtl"` for Urdu mode.
- `lang="ur"` attribute on typing area.
- Noto Nastaliq Urdu font loaded for Urdu text display.
- Urdu text stored as Unicode strings in lesson data.
- Keyboard highlight maps physical key to Urdu Unicode character based on selected layout.

---

## 8. On-Screen Keyboard

- `Keyboard.tsx` renders a full QWERTY layout.
- Receives `nextKey` prop (the physical key the user should press for the next character).
- Highlights that key with animation/glow.
- For English: shows standard English characters.
- For Urdu Phonetic: shows Urdu phonetic mapping from `urduKeyboardMap.ts`.
- For Urdu Standard: shows Urdu standard (Nastaliq) mapping from `urduKeyboardMap.ts`.
- Toggle to show/hide — preference saved in `settingsStore` (localStorage).

---

## 9. Certificate Generation

- Uses `jsPDF` + `html2canvas`.
- Certificate HTML template rendered off-screen, captured, converted to PDF.
- Triggered on client side — no server involvement.
- Certificate data: user display name, achievement text, WPM, date, Inspire Typing logo.
- Downloaded as `inspire-typing-certificate.pdf`.

---

## 10. Storage Strategy

- **Supabase Storage** used only for user profile images (optional feature, bucket: `avatars`).
- Lesson text content is stored in Supabase `lessons` table AND seeded from `src/data/` files.
- Certificates are NOT stored — generated on demand client-side.

---

## 11. Security Requirements

1. All Supabase tables have **RLS enabled**.
2. Users can only read/write their own data (enforced via `auth.uid()` in RLS policies).
3. Admin-only operations use `service_role` key ONLY server-side — NEVER in frontend.
4. Frontend only uses `anon` key (safe for public client).
5. No secrets in GitHub repo; all via Cloudflare environment variables.
6. Input sanitization: typing area accepts only keyboard input; no paste in test mode.
7. Admin route: additionally checks `profiles.user_role = 'admin'` server-side via RLS.

## 13. Environment Variables (Complete List)

| Variable | Used In | Source |
|----------|---------|--------|
| `VITE_SUPABASE_URL` | Frontend (supabase.ts) | Supabase Project → Settings → API → Project URL |
| `VITE_SUPABASE_ANON_KEY` | Frontend (supabase.ts) | Supabase Project → Settings → API → anon/public key |
| `VITE_GEMINI_API_KEY` | Frontend (aiCoach.ts) | Optional: Google AI Studio API Key. Leave empty to disable AI Coach. |

> **Note:** These are `VITE_` prefixed because Vite only exposes env vars with this prefix to the browser bundle. They must be set in Cloudflare Pages → Settings → Environment Variables → Production (before build). If `VITE_GEMINI_API_KEY` is not provided, the AI Coach gracefully hides and does not trigger errors.

## 14. Performance Considerations

- Lazy load pages with `React.lazy` + `Suspense`.
- Urdu font: use `font-display: swap`; preload in `index.html`.
- Lesson text data imported lazily per route.
- Recharts: load only on Dashboard page.
- jsPDF + html2canvas: lazy imported only when certificate is generated.
- Images: use WebP where possible; lazy loading with `loading="lazy"`.
